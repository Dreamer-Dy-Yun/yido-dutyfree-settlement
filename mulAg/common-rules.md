# common-rules.md

## 공통 원칙
- 역할 분리는 지시보다 **파일 수정 권한 분리**를 우선한다.
- 모든 작업은 작은 단위로 쪼개고, 동일 todo는 1개 목적/1개 책임으로 구성한다.
- 계획(plan)-할 일(todo)-리뷰(review)-완료(done) 순환을 강제한다.
- 선행조건이 완료되지 않은 작업은 수행하지 않는다.
- 기능/API/문서/계약이 바뀌면 관련 문서를 즉시 갱신한다.
- 기존 동작을 임의로 숨기지 않으며, 의도된 실패는 명시적으로 남긴다.

## 파일 접근 권한
- `수정 가능 파일`: 이 todo에서 직접 수정 가능한 파일.
- `생성 가능 파일`: 새로 만들 수 있는 파일.
- `읽기 전용 파일`: 참조만 가능.
- `수정 금지 파일`: 읽기/수정/삭제 모두 금지.
- todo에는 위 네 항목을 반드시 명시한다.

## 동일 파일 수정 제한
- 동일 파일은 동시에 하나의 Sub-Agent만 수정한다.
- 같은 파일을 여러 Sub-Agent가 다루는 경우 병렬 할당하지 않는다.
- 분리 가능한 경우 파일 단위로 선행 정리 후 다음 단계에서 후속 작업을 배정한다.
- 필요하면 순차(todo-1, todo-2)로 강제한다.

## 작업 단위 기준
- 1개 todo는 1개 책임 영역만 다룬다.
- 파일 범위가 겹치면 todo를 더 잘게 쪼개거나 선행 분해(todo-1 완료 후 todo-2)를 사용한다.
- 수정 범위를 넘는 판단이 나오면 즉시 review의 "남은 이슈"에 기록한다.

## 입력/출력 계약 기준
- Sub-Agent 간 연계가 필요한 todo는 입력/출력 계약을 명시한다.
- 입력에는 파일, 데이터 구조, 참조 함수/클래스를 포함한다.
- 출력에는 반환 형식, 새로 노출되는 인터페이스, 하위호환 범위를 포함한다.

## 인코딩 기준
- 모든 신규 텍스트 파일은 UTF-8로 작성한다.
- Windows PowerShell에서 한국어가 포함된 파일을 읽을 때는 `Get-Content -Encoding UTF8`을 사용한다.
- 출력이 깨져 보이면 파일 손상으로 판단하기 전에 UTF-8 유효성과 읽기 인코딩을 먼저 확인한다.
- 인코딩 정리 작업은 기능 코드 변경과 분리한다.

## plan 생명주기 관리 기준
- `plan/active`: 현재 진행/분해 필요 상태.
- `plan/done`: 모든 관련 todo-review가 완료되어 통합 검증된 상태.
- `plan/archived`: 대체, 폐기, 보류된 상태.
- 관련 todo/review가 모두 완료되어야 `active`에서 `done`으로 이동한다.
- 불완전/재설계 시 `active` 유지 또는 `archived`로 이동한다.

## review 필수 항목
- 수행 일시
- 참조 plan
- 참조 todo
- 수행 내용
- 변경 파일
- 생성 파일
- 검증 내용
- 남은 이슈
- QA 확인 요청 사항

## done 처리 원칙
- 완료 기준 충족 + 권한 위반 없음 + plan 참조 정합성 충족 시에만 done 처리.
- QA가 승인한 review만 done으로 이동한다.

## 금지 사항
- todo/plan/review에 없는 파일 수정
- todo에서 허용하지 않은 파일 생성 또는 수정
- 선행 조건 미충족 상태의 후행 todo 수행
- 병렬 작업에서 동일 파일 동시 수정
- review 없이 done 처리
- 완료된 plan을 active에 방치
