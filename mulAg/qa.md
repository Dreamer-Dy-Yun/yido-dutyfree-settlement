# qa.md

## review 검토 규칙
- review 문서의 필수 항목(수행 일시, 참조 plan/todo, 변경 파일, 검증 내용, 남은 이슈, QA 요청)을 우선 확인.
- todo의 완료 기준과 review의 완료 기준 일치 여부를 1:1로 점검.
- todo 지정 파일 경계 이탈 여부를 최우선으로 검증.

## done 처리 기준
- 완료 기준 충족.
- 권한 위반 없음.
- 선행 조건과 plan/todo 연관성 일치.
- 남은 이슈 없음(또는 사용자 의사로 보류 판단).

## plan 완료/보류/폐기 판단 기준
- 완료: 관련 todo의 review가 모두 done 처리되고, plan scope가 충분히 반영되었을 때 `plan/done`.
- 보류: 선행조건 미충족, 의존성 누락 등으로 일부 todo만 수행 가능할 때.
- 폐기: 대체 계획 존재 또는 요청 변경으로 해당 plan이 더 이상 유효하지 않을 때.

## 반려 기준
- todo 규칙 불일치
- 동일 파일 병렬 수정 흔적
- 완료 기준 미충족
- 수정 금지 파일 변경, 미지정 파일 생성/수정
- 검증 부재 또는 회피성 처리

## 파일 수정 권한 위반 검토
- 변경 파일이 todo 허용 범위 외인지 직접 비교.
- review가 todo 이외 파일을 수정했는지 확인.
- 수정 금지 파일 목록 위반 시 즉시 재작업 요청.

## 선행 조건 충족 여부 검토
- 이전 todo의 완료 상태, 리뷰 승인, plan active/dependency 상태를 확인.
- 선행 조건 미충족이면 설계 수정 혹은 todo 재배치.

## plan/todo 재작성 기준
- 반복 위반이 있거나 책임 경계가 흐려질 때 Orchestrator에게 plan 보강 지시.
- 구현 단계에서 새로운 범위가 생기면 해당 plan/todo를 분기해 재작성.
- 설계 의사결정이 바뀌면 plan/active 재수정 후 todo 재생성.
