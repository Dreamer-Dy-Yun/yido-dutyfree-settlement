# orchestrator.md

## plan 참조 규칙
- Orchestrator는 `plan/active/*`를 단일 진입점으로 사용한다.
- 각 plan은 최소 하나 이상의 todo로 분해해야 한다.
- 같은 파일을 여러 Sub-Agent가 수정해야 하는 경우 병렬 분해 금지.
- 파일 경계가 변경되면 즉시 plan에 반영하고, 관련 todo를 재작성한다.

## todo 작성 규칙
### 기본 형식
```markdown
# TODO: 작업명

## 참조 plan
## 목적
## 작업 범위
## 선행 조건
## 수정 가능 파일
## 생성 가능 파일
## 읽기 전용 파일
## 수정 금지 파일
## 입력
## 출력
## 작업 단계
- [ ] 1.
- [ ] 2.
## 완료 기준
## 주의사항
```

- `목적/범위/완료 기준`은 1문장 단위로 명확히 기재.
- 선행조건 미충족인 todo는 `보류` 또는 `다음 단계`로 분리.

## 작업 경계 정의 규칙
- todo는 1개 책임으로 제한한다.
- 입력/출력 계약이 필요하면 파일 단락을 명확히 작성한다.
- 범위가 겹치면 선행 todo로 병합하거나 분할 후 재배치한다.

## 파일 접근 권한 정의 규칙
- todo에서 `수정 가능`, `생성 가능`, `읽기 전용`, `수정 금지`를 명시한다.
- 수정 가능 파일은 해당 Sub-Agent가 실제 변경해야 하는 최소 집합만 남긴다.

## 선행 조건 정의 규칙
- plan 변경, 이전 todo의 done, review 승인 등 외부 조건을 선행 조건으로 기록한다.
- 선행 조건 불충족 발견 시 해당 todo는 `보류`로 유지.

## 입력/출력 계약 작성 규칙
- 입력: 참조 파일/데이터 구조/참조 컴포넌트.
- 출력: 수정/생성 파일과 외부 참조 인터페이스, 호환 범위.
- 누락 값은 임의 보정하지 않고 contract-level TODO로 남긴다.

## Sub-Agent 충돌 방지 규칙
- 동일 파일은 동일 시점 한 Sub-Agent만 담당.
- 병렬 충돌이 의심되면 todo를 재작성해 단위 분리 또는 순차(todo-1 -> todo-2).
- `plan/active`가 아닌 문서에서의 임의 지시 금지.
- 완료 기준 미충족 TODO는 plan으로 되돌아가 재정의한다.
